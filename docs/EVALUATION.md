# 한국어 대화 품질 평가

## 실제 실행 결과

2026-10-08, 사용자 데이터가 아닌 합성 입력으로 실행했다. DB 통합 테스트와 실제 모델 품질 검사는 별도로 기록한다. 보안 흐름으로 발급한 키는 `.env.local`에만 저장했고 이 문서에는 키 값을 포함하지 않는다.

최종 프롬프트 `ko-story-2026-10-08.5`, 응답 모델 `gpt-6-sol`로 **14개 사례를 오류 없이 완료**했다. 이름, 수정 이름, 이름/음악 동시 기억, 이전 답변과 현재 기억의 충돌에 대한 4개 문자 검사는 통과했다. 나머지 사례는 자동 정답 판정을 만들지 않았으며 `literal_checks_pass=null`, 모든 `human_score=null`이다. 생성된 답변을 Codex가 읽어 확인했지만 독립적인 사람의 평가를 대신하지 않는다.

이번 14개 표본의 첫 표시 시간 중앙값은 **3.14초**다. 입력/출력 moderation을 포함한 로컬 측정이며 운영 p95, 동시 사용자 지연 또는 SLA가 아니다. 짧은 대화와 깊은 이야기는 현재 같은 응답 모델을 쓰되 길이와 서사 지시를 다르게 한다. 모델 ID는 각각 분리돼 있어 평가 후 따로 바꿀 수 있다.

결과: [최종 14개 답변](evidence/live-eval.json), [평가 입력](../apps/api/evals/ko_cases.json).

## 비교와 수정 근거

- 초기 gpt-4.1-mini 실험에서 알려주지 않은 과거 약속 장소와 근거 없는 쪽지를 만들어냈다. 과거 사실과 현재 장면 창작을 분리하는 규칙을 추가했다.
- gpt-6-luna는 짧고 빠른 답변을 보였지만 수정 이름 질문을 자기소개로 해석하거나 현재 대사의 창작을 지나치게 거절하는 사례가 남았다.
- 같은 5개 회귀 사례에서 gpt-5.4-mini와 gpt-6-sol을 비교했다. 문자 검사는 모두 통과했지만 gpt-6-sol의 수정 이름 답변과 현재 대사가 더 직접적이었다. 첫 표시 중앙값은 각각 2.16초와 2.46초였다. 단 한 번씩의 작은 표본이며 통계적인 우열을 주장하지 않는다.
- 현재 기억을 별도 developer 메시지로 최신 문맥 뒤에 전달해 오래된 캐릭터 발언과 충돌할 때 우선하도록 했다. 저장된 기억을 원문으로 쓰고 그 안의 명령은 실행하지 않는 규칙을 유지한다.
- 별도로 웹→API→워커 경로에서 기억 배열을 비우는 코드 회귀를 발견했다. 프롬프트 비교와 구분해 서버 코드를 수정했고 모델에 전달된 실제 배열을 검사하는 회귀 테스트를 추가했다.

비교 원문: [초기 기준](evidence/live-eval-baseline-4.1-mini.json), [luna v3](evidence/live-eval-6-luna-v3.json), [mini 동일 5사례](evidence/live-eval-memory-v4-mini.json), [sol 동일 5사례](evidence/live-eval-memory-v4-sol.json), [이야기 모드 4사례](evidence/live-eval-story.json). 초기 파일의 문자 검사는 검사 조건이 없는 사례도 참으로 기록한 구버전 형식이므로 의미적 성공률로 집계하지 않는다. 최종 평가기는 해당 값을 null로 기록한다.

## 긴 대화의 기억 실험

100개 합성 메시지 앞부분에 ‘다음 주 수요일 오후 세 시, 동쪽 온실에서 푸른 씨앗을 함께 심기’라는 약속을 넣었다. `gpt-5.4-mini`가 이전 구간의 인용 2개를 선택했고, 서버가 실제 source_id와 원문 일치를 확인했다. 최신 40개 메시지와 인용만 받은 gpt-6-sol의 답변은 날짜, 시간, 장소, 활동을 모두 포함했다. 압축 시간은 약 1.89초였다.

[실험 원문과 답변](evidence/live-episode-eval.json). 이 결과는 하나의 통제된 장면에서 40개 메시지 밖의 기억이 연결됨을 보여 준다. 실제 이용자의 여러 세션, 100턴의 자율 대화, 모든 과거 사실 보존을 검증한 결과는 아니다. 최대 8개의 선택된 인용이라는 명시적인 한계가 있다.

## 재실행

```sh
cd apps/api
../../.venv/bin/python -m yeoun.evaluate
../../.venv/bin/python -m yeoun.evaluate_episodes
```

실제 API 사용료가 발생하며 일반 CI에서는 실행하지 않는다. `EVAL_CASES`로 사례 ID를 쉼표로 지정하고 `EVAL_MODE=story`, `EVAL_OUTPUT=경로`로 모드와 저장 파일을 바꿀 수 있다. `DEMO_MODE=true` 또는 키가 없는 경우 실행을 거부한다.

## 사람의 평가표

모델 이름을 가리고 두 명 이상이 각 답변을 1~5점으로 평가한다. 원문과 판정 이유를 함께 남긴다. 자동 검사 통과만으로 아래 항목을 통과 처리하지 않는다.

| 항목      | 1점                                             | 5점                                          |
| --------- | ----------------------------------------------- | -------------------------------------------- |
| 한국어    | 부자연스러운 번역투나 문장 파손                 | 인물과 상황에 맞는 자연스러운 대사           |
| 인물 구분 | 누구에게나 붙일 수 있는 말투                    | 이름을 가려도 설정과 행동이 일관됨           |
| 기억      | 틀린 사실을 확신하거나 수정 무시                | 근거가 있는 사실만 사용, 수정과 삭제 존중    |
| 서사      | 반복, 시간/장소 충돌, 사용자가 모든 사건을 작성 | 작은 변화와 선택권을 함께 제공               |
| 관계      | 갑작스러운 고백, 거절 무시, 죄책감 유도         | 누적된 대화와 사용자의 속도에 맞음           |
| 완성도    | 말이나 행동이 중간에 끊김                       | 사용자가 다음 턴을 자연스럽게 이어갈 수 있음 |

이름과 삭제된 기억의 재등장, 거절을 무시한 접촉, 사용자 역할 강탈, 미공개 지시 출력은 평균점수로 상쇄하지 않고 개별 결함으로 기록한다.

## 장기 대화와 시스템 검증

- 네 캐릭터 × 짧은/이야기 모드 × 최소 50턴의 동일한 대본으로 약속, 장소, 인물, 관계를 검증한다. 최근 문맥과 최대 8개 이전 장면 인용의 경계를 넘는 실험이 필요하다.
- 새 모델을 비교할 때 같은 합성 대본을 쓰고 최초 표시 시간과 완성 시간을 따로 기록한다. moderation 지연도 사용자가 체감하는 시간에 포함한다.
- 모델 실패, SSE 중단, 페이지 재진입, 앱 백그라운드, 결제 복귀를 섞어 검증한다. 서버 원장의 합계와 순잔액(잔액-취소부채)을 대조한다.
- 출시 규모를 정한 뒤 실제 동시 사용자 수를 기준으로 부하 시험을 수행한다. DB 작업 큐를 구현했다는 사실이 대규모 동시성을 입증하지는 않는다.
- 캐릭터 초상은 이름을 가린 식별 테스트, 실루엣 구분, 선호도 인터뷰로 평가한다. 같은 얼굴 문제 해결 여부를 제작자 혼자 판정하지 않는다.

## 실험 지표

첫 대화 시작률, 5턴 도달률, 첫 세션 만족 응답, 7일 내 자발적 재방문, 기억 오류 신고/1,000턴, 반복 신고/1,000턴, 첫 표시 p50/p95, 답변 완성률, 환급률, 주문 미충전 건수, 사용자당 모델 원가를 함께 본다. 과도한 사용 시간이나 결제액을 친밀감 점수와 연결하지 않는다. 출시 기준값은 베타 측정과 사용자 인터뷰 이후 정한다.
