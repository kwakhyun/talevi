# 공개 전 이력 정리와 유료 평가 보존

2026-10-15, 사용자의 요청에 따라 원본 저장소 공개를 준비하며 Git 이력을 정리했다. 과거 유료 모델 검증 자료를 삭제하거나 새로 실행하지 않았다. 전체 소스와 자료는 `kwakhyun/talevi`에 통합하고, `talevi-portfolio`에는 이전 안내를 남긴다.

## 바꾼 내용

기존 공개 대상 `main`은 5개 커밋이었다. 별도 복제본에서 `git-filter-repo 2.47.0`의 민감정보 정리 기능을 사용해 다음 로그에 있던 로컬 프로젝트 절대경로를 `<PROJECT_ROOT>`로 치환했다.

| 파일 | 치환 위치 |
| --- | ---: |
| `docs/evidence/cast-final-2026-10-10/extended-run.log` | 4 |
| `docs/evidence/cast-v9-2026-10-10/extended-run.log` | 4 |
| `docs/evidence/cast-v11-2026-10-10/extended-run.log` | 28 |
| **합계** | **36** |

파일 자체, 오류 추적의 종류와 행 번호, 실패와 재개 내용은 남겼다. 과거 5개 커밋을 각각 전후 비교했으며 이 세 로그 외의 파일 내용에는 변화가 없었다. 현재 정책과 README, 평가 자료 색인은 그 위에 별도의 공개 준비 커밋으로 추가했다.

원본과 기존 포트폴리오의 Git bundle, 정리 전 평가 파일 해시는 Git에서 제외한 로컬 비공개 백업에 보관한다. 정리 전 이력을 공개 저장소의 백업 브랜치나 태그로 다시 올리지 않는다.

## 유료 검증 자료가 보존됐는지 확인한 방법

1. 정리 전 `docs/evidence/`의 추적 파일 126개를 목록화하고 SHA-256을 계산했다.
2. 정리 후 경로 목록이 정확히 같은지 검사했다. 삭제된 평가 파일은 0개다.
3. 123개가 바이트 단위로 동일함을 확인했다. 모든 JSON/JSONL 응답과 상태, 측정 결과, 평가 manifest 및 화면 자료가 여기에 포함된다.
4. 차이가 나는 3개 로그는 경로 치환만 적용한 결과와 정확히 일치한다. [파일별 전후 해시](publication-evidence-preservation.json)를 공개한다.
5. 최종 v11의 240개 기본 응답, 916개 후속 응답, 관계 60개, 현실 구분 12개, HTTP 8개, 추가 회귀 14개, 한국어 기억 6개의 자료를 유지했다. 916개에는 900턴과 모드 비교 12개, 이전 실패 입력 4개가 포함된다. 합계 1,256건을 중복 합산하지 않았다.

초기 모델 비교와 100개 합성 메시지의 기억 실험, 개편 당시 24회 검사, v11 이전 실패와 재검증도 [전체 유료 평가 색인](MODEL-EVALUATION-ARCHIVE.md)에서 찾을 수 있다. 보존한 원문을 새 자동 검증 144개나 기록 재생 영상의 결과로 대체하지 않았다.

기존 `interruption-and-resume.json` 등에 기록된 로그 해시는 **정리 전 원본**을 가리킨다. 당시 증거를 바꾸지 않기 위해 그 기록은 그대로 두었으며, 전후 해시 목록이 지금 공개한 로그와의 대응을 설명한다. 기록된 프롬프트와 소스 파일 해시도 당시 검사 대상의 값이며 현재 전체 코드의 해시로 바꾸지 않았다.

시연 영상의 `2f51276`은 당시 실제 검사한 커밋이다. 현재 같은 서비스 소스를 가리키는 커밋은 `912611f`다. 영상과 과거 평가 기록을 다시 만들지 않고 이 대응을 제공한다. 검사 대상 코드가 같으므로 문서 공개를 위해 유료 모델 평가나 전체 자동 테스트를 다시 실행하지 않았다.

## 공개 전 검사

- Gitleaks 8.30.1 기본 규칙과 전체 비밀값 마스킹으로 정리 전후의 공개 대상 Git 이력을 검사했다. 탐지 결과는 0건이었다.
- 공개 대상의 Git 객체 전체를 추가 검사했다. 정리 전 로컬 경로 36곳이 있었고 정리 후에는 검출되지 않았다. 현재 로컬 환경의 비밀값과 일치하는 내용도 검출되지 않았다. 비밀값은 보고서에 기록하지 않았다.
- 기존 소개 저장소의 전체 이력도 Gitleaks에서 탐지 0건이었다.
- 과거 Actions 실행 5건의 로그 파일 50개를 로컬 백업하고 Gitleaks로 검사했다. 탐지 0건이었다. 로그 50개에서 개인 로컬 경로와 현재 비밀값의 일치도 검출되지 않아, 원격 CI 실행 기록은 삭제하지 않고 검증 이력으로 보존한다. 이전 CI는 이전 커밋 ID를 계속 참조하므로 새 구현의 CI와 구분한다. 이는 유료 모델 평가 원문과 별개다. [기존 CI 결과의 보존 요약](publication-ci-history.json)
- 원격에 PR, 포크, 추가 브랜치/태그 및 Actions 첨부 산출물이 없음을 확인했다. 원격 `main` 갱신에는 확인한 기존 SHA를 조건으로 한 `--force-with-lease`를 사용한다.

검사는 알려진 비밀 패턴, 로컬 경로, 현재 비밀값과 파일 무결성에 관한 것이다. 모든 이미지의 OCR, 전 의존성 보안 감사 또는 모든 개인정보의 부재를 보증하지 않는다. 공개 자료에는 합성 대화와 가상 인물이 포함된다.

## 정리 범위의 한계

이 기록은 공개 브랜치에서 도달 가능한 Git 이력과 현재 공개 파일을 정리한 결과다. GitHub가 보관하는 도달 불가능한 옛 커밋의 캐시나 이미 내려받은 사본을 완전히 삭제했다는 뜻은 아니다. GitHub 문서도 이력 재작성만으로 서버의 모든 캐시가 제거되지는 않는다고 설명한다. 이번 검사에서는 실제 자격증명 유출을 찾지 못했으며 제거한 것은 로그의 로컬 경로다. [GitHub 공식 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

다른 기기에 정리 전 clone이 있다면 새로 clone한다. 예전 브랜치를 합치거나 모든 로컬 참조를 mirror push하면 가린 경로가 돌아올 수 있다. 로컬 백업은 공개 원격에 올리지 않는다.
