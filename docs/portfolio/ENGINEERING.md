# 대화 경험을 지탱하는 설계

테일비는 LLM 답변뿐 아니라 재연결, 비용 차감, 기억의 변경과 관계의 근거까지 하나의 대화 흐름으로 다룹니다. 구현 원문과 캐릭터별 프롬프트는 비공개로 유지하고, 여기에는 문제와 설계 판단을 정리했습니다.

## 기억 수정과 이야기 보존

처음에는 기억을 수정할 때 과거 문맥을 전체 초기화했습니다. 오래된 이름이 다시 등장하는 것은 막았지만, 같은 문맥에 있던 다음 날 약속까지 잃었습니다.

변경한 구조에서는 원본 대화와 AI용 문맥을 분리합니다. 수정 또는 삭제한 값만 AI 문맥에서 무효화하고, 무관한 문장과 사건은 남깁니다. 사용자 사실은 원문 근거가 있는지 확인하며 이름, 음료와 음악 등의 취향, 약속을 별도 항목으로 저장합니다. 수정과 삭제, 잠금은 모델 제안보다 서버의 상태를 우선합니다.

실제 HTTP → DB → 워커 → 모델 → SSE 검사에서 이름과 음료를 바꾼 뒤에도 기존 약속 시간과 장소가 유지됨을 확인했습니다. 여러 날짜의 일정을 관리하는 캘린더나 무제한 기억을 구현한 것은 아닙니다.

## 관계 변화와 캐릭터의 판단

메시지 수에 비례해 신뢰가 올라가면 의미 없는 입력으로도 깊은 관계에 도달합니다. 이를 막기 위해 관계 신호와 실제 발언 근거를 함께 검사합니다. 반복 문장과 점수 조작 요청은 제외하고, 협력과 자기 공개, 갈등, 화해를 구분합니다.

각 캐릭터에는 문장 리듬, 감정 반응, 내적 갈등, 확정된 개인 과거, 관계 단계별 연기 지침이 있습니다. 깊은 신뢰는 자동으로 연애나 신체 접촉에 동의했다는 뜻이 아닙니다. 거절과 거리 요청은 존중하며 결제액은 친밀도 조건에 사용하지 않습니다.

규칙 검사에서 30명 모두 의미 없는 입력 85회로는 신뢰가 오르지 않았습니다. 실제 모델의 첫 만남과 깊은 신뢰 응답은 별도 통제 실험으로 비교했습니다. 자연스러운 장기 관계의 만족도는 이용자 평가가 필요합니다.

## 사건의 추가보다 선택의 결과

이야기는 현재 장소와 목표, 갈등, 선택, 결과와 실마리를 저장합니다. 같은 실마리를 해결했다고 반복 처리해서 챕터가 올라가지 않도록 합니다. 이전 대화를 압축할 때에는 선택된 과거 인용과 최근 문맥을 함께 쓰며, 확정된 사용자 사실은 별도 기억에 유지합니다.

## 한 번의 전송을 끝까지 처리하기

1. 인증과 대화 소유권을 확인합니다.
2. 요청 식별자와 본문을 비교해 중복 요청을 처리합니다.
3. 대화 작업, 사용자 메시지, 비용 차감을 같은 트랜잭션에 기록합니다.
4. 워커가 DB의 작업을 선점하고 대화 문맥을 구성합니다.
5. 모델의 답변과 상태 제안을 검증합니다.
6. 검수된 답변을 SSE 이벤트로 전달하고 결과와 상태를 저장합니다.
7. 생성 실패 시 원장을 기준으로 한 번만 환급합니다.

클라이언트 연결이 끊겨도 작업은 DB에 남고, 재연결은 마지막 이벤트 이후부터 받습니다. 현재 작업 규모에는 PostgreSQL 기반 큐를 선택했습니다. 대규모 동시 접속을 입증한 구조는 아니며 실제 처리량과 비용 측정이 필요합니다.

## 완성본 검사와 응답 지연의 절충

초기 평가에서는 정상 대화도 일부 출력된 뒤 검수에 걸리는 사례가 있었습니다. 현재는 완성된 답변을 검사한 뒤 전달하고 필요하면 한 번 다시 생성합니다. 생성 중인 원시 토큰을 바로 보여 주는 방식은 아닙니다.

이 변경은 중도 노출 문제를 줄였지만 최초 표시를 늦췄습니다. 최종 기본 검사에서 짧은 대화 중앙값은 3.74초, 이야기 모드는 10.27초였습니다. 지연을 별도로 측정하며, 단지 더 긴 답변을 낸다는 이유로 품질이 높다고 판정하지 않습니다.

## 결제와 클라이언트의 경계

웹은 Toss 승인 조회, 앱은 RevenueCat 구매 이벤트를 서버에서 확인하도록 구현했습니다. 클라이언트 구매 완료 화면이나 URL의 금액을 그대로 잔액으로 믿지 않습니다. 원장, 중복 승인, 실패 환급을 테스트하지만 상점 개통과 실제 결제, 스토어 실기기 검증은 아직 남아 있습니다.

## 검토할 때 볼 수 있는 자료

비공개 코드 검토에서는 기억 수정 전후의 문맥, 관계 변경의 근거, 턴의 원자적 저장, 중복 전송과 환급, 모델 실패 및 SSE 재연결 테스트를 중심으로 설명할 수 있습니다. 공개 범위의 수치와 한계는 [검증 결과](VALIDATION.md)에 정리했습니다.
