# 원본 저장소 공개와 포트폴리오 통합 검토

검토일: 2026-10-15. 기준: 원격 `main`의 `2f512767a1461d58d8cf84675df8a254a7aecc33`. 이번 작업은 검토이며 저장소 공개 범위, 삭제, 아카이브, Git 이력을 변경하지 않았다.

## 권고

**채용 포트폴리오가 우선이라면 정리한 원본 `talevi`를 공개하고, 소개와 시연 영상, 설계, 검증, 소스를 한곳에 모으는 방향을 추천한다.** 검토자가 설명에서 구현과 테스트로 바로 이동할 수 있고 문서 두 벌을 따로 갱신할 필요가 없어진다. 공개 서버 운영은 이 결정의 전제 조건이 아니다. 로컬 시연 영상과 재현 방법으로 서비스의 동작을 보여줄 수 있다.

다만 기존 `talevi-portfolio`는 즉시 삭제하기보다 원본으로 이동했다는 안내를 남긴 뒤 아카이브하는 편이 낫다. 이미 지원서 등에 사용한 링크를 유지할 수 있고, 이후 관리할 실질적인 저장소는 원본 하나다. GitHub의 아카이브는 저장소를 읽기 전용으로 전환하며 되돌릴 수 있다. [GitHub 아카이브 안내](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories)

이 권고는 캐릭터 프롬프트와 구현을 다른 사람이 내려받을 수 있다는 점을 받아들이는 경우에 해당한다. **무단 복제 자체를 막는 것이 우선이면 원본 비공개 구성을 유지해야 한다.** 공개 저장소는 라이선스가 없어도 GitHub에서 열람과 포크가 가능하며, 나중에 비공개로 바꾸더라도 기존 포크와 로컬 사본은 사라지지 않는다. [GitHub 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

## 공개 전 점검 결과

원본 이력의 고유 파일 내용 308개를 검사했다. 텍스트 237개와 바이너리 71개이며, 현재 추적 파일은 304개다. 자주 쓰이는 공급자 토큰, 개인키, 인증 문자열, 비밀값 대입, DB 접속 문자열, 이메일, 로컬 경로를 검색하고 현재 로컬 환경의 비밀값과도 내용 일치를 비교했다. 비밀값과 인증 정보는 보고서나 검사 출력에 기록하지 않았다.

이 검사는 자동 패턴과 범위별 확인이며, 전문 비밀 탐지 도구의 전체 규칙이나 이미지 OCR을 적용한 감사는 아니다. 검출되지 않았다는 결과가 모든 민감 정보의 부재를 보증하지 않는다. 이번 시연을 위해 이후 생성되는 파일은 위 숫자에 포함하지 않았다.

## 코드 외에 함께 공개되는 자료

**캐릭터 차별화의 근거도 공개된다.** `apps/api/yeoun/catalog.py`, `personas.py`, `engine.py`에는 인물 설정과 말투, 관계별 행동, 프롬프트 구성 및 품질 검사가 있다. `docs/character-prompts*.json` 3개에는 이미지 생성 지시가 있다. 코드만 공개하고 이 부분을 숨긴다는 선택은 현재 구조 그대로는 성립하지 않는다.

**평가 원문은 합성 대화지만 모두 읽을 수 있게 된다.** `docs/evidence/`에는 파일 126개, 약 25.8 MB의 이력과 응답 원문이 있다. 최종 v11 문서는 실제 이용자 대화가 아닌 합성 입력이며 독립적인 사람 평가자가 없었다고 명시한다. 그 출처와 한계를 유지해야 한다. 과거 실패나 안전성 검사 입력은 맥락 없이 보면 제품의 일반 응답처럼 보일 수 있으므로 README에서 최신 검증으로 안내하고 과거 자료에는 버전과 검사 목적을 표시하는 것이 좋다.

**생성 이미지의 원본도 내려받을 수 있다.** 캐릭터 파일은 약 73.9 MB이며 생성 이력은 [자산 문서](ASSETS.md)에 기록돼 있다. 외부 서비스 이미지나 기존 IP를 사용하지 않았다는 제작 기록은 있지만, 독립적인 유사성 조사나 권리 심사를 완료했다는 뜻은 아니다. AI 생성 자산의 독점권을 보장한다고 표현하지 않는다.

`AGENTS.md`와 자산 문서에 적힌 내부 제작 선호도 공개 범위에 들어간다. 비밀이나 인증 정보는 아니지만, 채용 검토자가 읽게 될 내부 작업 기준이라는 점은 인지해야 한다.

## 권리 안내와 의존성

현재 [RIGHTS.md](../RIGHTS.md)는 권리를 유보하며 공개 포트폴리오용 안내를 제공한다. 공개 전환만으로 오픈소스가 되는 것은 아니다. 무단 재판매나 자기 제작물로 제시하는 행위를 허용하지 않는 현재 방향을 유지한다면, 설명에는 **소스 공개 포트폴리오**라고 쓰는 편이 정확하다. 단순 공개를 위해 재사용을 폭넓게 허용하는 MIT 라이선스를 임의로 추가할 이유는 없다. GitHub의 열람과 포크 권한까지 차단할 수는 없다. [GitHub 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

공개 전에는 `RIGHTS.md`의 “구현 소스는 별도 비공개 저장소”라는 문구와 [기존 공개 정책](PUBLISHING.md), 포트폴리오 README를 실제 결정에 맞춰 갱신해야 한다. 실제 검토자가 소스를 실행하고 테스트할 수 있게 할 범위도 권리 안내에 일관되게 명시하는 것이 좋다.

JavaScript 잠금 파일에는 MIT, Apache, ISC, BSD 외에 libvips 관련 LGPL, 일부 MPL 등의 의존성 표시가 있다. 추적 대상에 `node_modules`나 폰트 바이너리는 없으며 웹은 Google Fonts의 Noto Sans KR을 외부 요청한다. 자체 코드의 권리 유보가 제3자 패키지의 라이선스를 덮어쓰지 않는다. 소스 공개와 별개로 실행 파일이나 앱 번들을 배포할 때는 실제 포함 패키지의 고지와 라이선스 조건을 확인해야 한다. 이 검토는 잠금 파일의 표시 확인이며 모든 전이 의존성의 법률 검토가 아니다.

## 실제 통합을 선택할 때의 순서

1. 시연 영상, 기술 설명, 최신 자동 검증 결과를 원본 README에서 바로 찾게 한다. 과거 실제 모델 평가와 최신 자동 회귀 검사를 구분한다.
2. 공개할 파일 범위를 정하고 위 로그 경로 및 관련 과거 이력을 정리한다. 영상에는 계정, 키, 터미널 환경 파일, 실제 개인 대화를 포함하지 않는다.
3. 현재 비공개 안내를 통합 운영 방침으로 바꾸고 소스와 자산의 재사용 범위를 정한다.
4. 최종 커밋과 Actions 로그를 다시 검사한 후 원본을 공개한다. 공개되면 코드와 Actions 이력이 모두 보인다. [GitHub 공개 범위 변경 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)
5. 기존 소개 저장소에 원본 링크와 이전 안내를 남기고 아카이브한다. 기존 링크를 더 이상 사용하지 않고 삭제를 원할 때에만 별도로 삭제한다.

삭제는 통합에 필수적이지 않다. GitHub는 일부 삭제 저장소의 90일 내 복원을 지원하지만 항상 복구할 수 있는 것은 아니며, 공개 저장소를 삭제해도 포크는 삭제되지 않는다. 따라서 삭제를 사본 회수 수단으로 보아서는 안 된다. [GitHub 삭제 안내](https://docs.github.com/en/repositories/creating-and-managing-repositories/deleting-a-repository)

## 이번 검토의 실행 범위

GitHub에는 읽기 요청만 보냈다. 원본은 계속 비공개이고 소개 저장소도 그대로 공개 상태다. 저장소 삭제, 공개 전환, 아카이브, 외부 협업자 초대, 라이선스 변경, 이력 재작성, 공개 배포는 하지 않았다. 다음 실행 여부를 판단할 수 있도록 이 보고서만 추가했다.
