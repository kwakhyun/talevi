## 서버 테스트가 확인하는 동작

공개 캐릭터의 비밀 설정 비노출, 스트림과 기억의 저장, 중복 요청의 단일 과금, 동시 요청, 다른 본문으로 멱등 키 재사용 거절, 대화별 직렬 처리, 지갑 음수 방지, 실패 답변의 단일 환급, 오래된 작업 회수, 최신 lease 재검사, 사용자 간 데이터 접근 차단, 기억 수정 잠금과 삭제 표식, 자동 기억 끄기, 결제 중복 승인, 금액 위변조 차단, native 세션과 해지, 체험 계정의 가입 후 데이터 보존, 출처/입력 검증, SSE cursor 재연결, 피드백, 내보내기, API 키 부재 시 차감 방지, 한국어 이름 추출, 관계 경계, 초기 인사의 모델 문맥 포함을 검증했다.

추가 native 결제 테스트는 서명 검증, 잘못된 환경/상품 거절, webhook 중복 충전 방지, 취소 부채, 취소가 구매보다 먼저 도착하는 경우, 여러 대화에서 동일 멱등 키가 충돌한 경우의 차감 rollback을 포함한다. 외부 공급자는 실제로 호출하지 않았다.

추가 장기 기억 테스트는 잘못된 인용/출처 거부, 최신 원문 보존, 실패/삭제 메시지 제외, DB 저장, 기억 초기화, 압축 실패 시 최신 대화 유지, 사용 중지 시 프롬프트 제외, 실제 모델 호출에 수동 기억 전달까지 확인한다.

## 브라우저 관찰

1. 첫 장면에서 대화를 열고 합성 문장 ‘내 이름은 민지야. 나는 재즈를 좋아해.’를 보냈다. 스트리밍 후 이름과 취향 카드가 생성되고 잔액이 30에서 29로 변했다.
2. 기억 노트에서 이름을 ‘민’으로 수정했다. 이후 ‘내 이름을 기억해?’에 예시 엔진이 수정한 이름과 취향을 사용했다. 이 검사는 UI→API→DB→프롬프트용 기억 입력의 연결을 검증하며 모델 자체의 기억 추론 검사는 아니다.
3. 500 빛 테스트 충전 후 잔액이 29에서 529로 변하고 원장에 한 행이 생겼다. 실제 결제는 없었다.
4. 390×844 화면에서 문서 너비가 390px임을 확인했다. 계정 진입점이 숨는 문제를 수정한 뒤 ‘내 계정’과 지갑 진입을 다시 확인했다.
5. 테스트 후 뷰포트 크기를 원래대로 복원했다.

실제 모델 연결 후에도 같은 합성 계정에서 검증했다. 장기 기억 기능을 편집하며 워커가 기억 목록을 비우는 회귀가 생겨, UI의 노트와 답변이 달랐다. 모델 입력을 직접 검사하는 테스트로 원인을 재현하고 수정했다. 수정 후 답변은 이름 ‘민’과 음악 ‘재즈’를 모두 사용했다. 모델의 문자 포함 평가만으로 서버 전달 버그를 검출할 수 없었으므로 서버→모델 입력 검사를 추가했다. 지문과 굵은 글씨의 `*` 표현이 섞이는 렌더링도 고쳤다.

실제 웹에서 이야기 모드의 ‘잠시 쉬어가기’를 선택한 뒤 3 빛만 차감되고 제2장으로 진행됐다. 답변은 수정된 이름을 사용하며 휴식 장면을 이어갔다.

## 수정한 주요 결함

- Expo SDK 57과 최신 React Native의 버전 불일치 때문에 최초 native export가 실패했다. `expo install --fix`로 RN 0.86.3, React 19.2.3 등 공식 권장 조합으로 맞춘 뒤 양 플랫폼 export가 통과했다.
- SQL의 NULL 비교로 초기 인사가 모델 문맥에서 빠지는 문제를 수정하고 회귀 테스트를 추가했다.
- 오래된 작업을 조회한 직후 정상 작업이 갱신되는 경쟁 상황에서 잘못 환급하지 않도록 잠금 안에서 lease를 다시 검사한다.
- 서로 다른 대화가 같은 client_id를 동시에 사용하는 경우 고유 제약 충돌을 409로 처리하고 크레딧 차감을 rollback한다.
- 모달 바깥의 오류 메시지가 가려지지 않도록 모달 내부에도 오류를 표시한다.
- SSE 재시도 때 AbortSignal 리스너가 쌓이지 않도록 정리한다.

## 의존성 검토

npm audit의 초기 결과는 23개 패키지 경고였다. `xcode`가 사용하는 `uuid`를 호환 API를 유지하는 11.1.1로 override하고 잠금 파일을 갱신했다. 이후 설치 결과에는 **16 high 패키지 경고**가 남는다. 이는 16개의 서로 다른 취약점이라는 뜻이 아니라 주로 다음 두 전이 의존성이 상위 Expo/Metro 패키지들에 전파된 결과다.

- [braces 깊은 패턴 처리](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm): 설치/조회 시 최신 버전 3.0.3까지 영향 범위.
- [node-forge RSA 서명 검증](https://github.com/advisories/GHSA-86w9-cpqp-85rv): 설치/조회 시 최신 버전 1.4.0까지 영향 범위.

자동 fix가 제안한 Expo 44로의 큰 버전 역행은 적용하지 않았다. 이 의존성은 주로 모바일 개발/빌드 도구 체인에 있으나, 실제 공격 경로 검토와 상위 패치 확인을 마친 것은 아니다. 외부의 임의 프로젝트/파일을 CI 빌드 입력으로 받지 않고, 공개 출시 전에 보안 검토와 의존성 갱신을 다시 수행한다. ‘취약점 0’이라고 주장하지 않는다.

## React 구현 검토

웹 결제 SDK는 결제할 때만 동적으로 불러오고, 독립적인 초기 요청은 병렬로 읽는다. React 렌더링에 사용자 원문 HTML을 삽입하지 않는다. Next Image를 사용하며 카드와 대화의 key는 저장된 ID를 쓴다. 스트림 중단과 effect 정리, reduced-motion CSS, native dialog의 포커스 동작을 검토했다. 정식 스크린리더 및 WCAG 적합성 검사는 아직 수행하지 않았다.
